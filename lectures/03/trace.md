# 第3回：時間と実行フローのログ

## 実行

仮想環境と `GEMINI_API_KEY` を設定済みのターミナルで、リポジトリ直下から実行する。

```sh
python -m app.agent --trace --trace-dir lectures/03/results/basic_trace/manual "LoRAとQLoRAの違いは？"
```

`--trace` は従来のツール履歴表示、`--trace-dir` は実行中の時系列表示とファイル保存を行う。単独でも併用でも使える。保存先の中には実行日時とタイムゾーンを含むフォルダが毎回作られ、過去の結果を上書きしない。

## 保存ファイル

| ファイル | 内容 |
| --- | --- |
| `timeline.txt` | 実行開始からの経過時間、LLM・ツールの開始と終了、所要時間 |
| `trace.md` | 実行終了時に生成する詳細ログ。時間順に、送信指示・全会話履歴・ツール定義・LLM応答・ツールの引数と戻り値をまとめて読める |
| `events.jsonl` | 同じイベントの機械可読ログ。タイムゾーン付き時刻、識別子、ツール名、関連ファイル名など |
| `llm-001-request.json` | 1回目のモデル呼び出しの指示・メッセージ履歴・ツール定義 |
| `llm-001-response.json` | 1回目のモデル応答。ツール呼び出し要求も含む |
| `llm-002-request.json` | 2回目のモデル呼び出し。直前の応答とツール結果を含む履歴を確認できる |
| `llm-002-response.json` | 2回目のモデル応答 |
| `tool-001-input.json` | ツール名、引数、呼び出しID、要求したLLM呼び出しの識別子 |
| `tool-001-output.json` | ツールの返り値。従来のtraceと異なり、120文字で切り詰めない |
| `summary.json` | 実行の成否、全体時間、モデル・ツールの計測回数、usage、最終回答 |

番号は実行順に増える。開始と終了は識別子で対応づける。複数ツールの開始が、いずれかの終了より前に記録されていれば、実行区間が重なっていたと読める。

## 計測範囲

- 使用中のPydantic AI 2.57.0の `wrap_model_request` と `wrap_tool_execute` を利用した。新しい依存関係やログ用の外部サービスは追加していない。
- 所要時間は `perf_counter()` の差分で測る。時刻はローカルのタイムゾーン付き日時で記録する。
- LLMの時間は通信待ちやSDK内部の再試行などを含む、呼び出し全体の観測時間である。モデルの内部計算だけの時間や、HTTPの各試行の時間ではない。
- ツールの時間は、引数検証後の実行フック内で観測した時間である。フック内の処理やスレッドへの実行委譲にかかる時間も含む。
- JSONの入力はPydantic AIのモデル抽象化の段階で取得する。Gemini向けに変換済みの生のHTTPリクエストではない。入出力に内部思考を表示する機能は加えていない。
- ログ書き込み自体にも時間がかかるため、各処理時間の合計と全体時間は一致しない。
- モデルやツールが例外で終了した場合も、開始済みイベントと例外の種類を残す。記録処理そのものが失敗した場合は、そのエラーが伝播する。
- 認証ヘッダー・環境変数の一覧は記録しない。環境変数 `GEMINI_API_KEY` の値が内容に現れた場合は伏字にする。質問・検索結果・回答自体はログに含まれるので、提出するログの内容は確認する。

参考：[Pydantic AI公式：Custom Capabilities](https://pydantic.dev/docs/ai/capabilities/custom/)

## 基礎課題としての比較

ログを作るだけでなく、次の手順で基礎課題の「指示やdocstringの変更前後を比べる」実験を行った。比較結果は [answer.md](answer.md) の宿題欄に記載した。

1. 変更前の `INSTRUCTIONS` と同じ質問で実行し、baselineとして保存する。
2. `INSTRUCTIONS` の「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」の1行だけを外す。
3. 同じ質問を実行し、別フォルダへ保存する。モデル・ツール・それ以外の指示は変えない。
4. ツール名・引数・回数、LLM呼び出し回数、回答、所要時間を比較する。
5. その状態から、検索ツールのdocstringの「答える前に使うこと」という文だけも外し、同じ質問で追加比較する。用途と引数の説明は残す。

元の条件を1回、全体指示の1行だけを外した条件を4回、さらにdocstringの検索を促す文も外した条件を2回実行した。すべての試行でLoRAとQLoRAを別々に検索し、LLM呼び出し2回・検索2回だった。各条件の試行数は少なく、速度差の原因を指示変更だけに帰属させない。

ログの一覧は [results/README.md](results/README.md) を参照する。現在のコードは、全体指示とdocstringの両方から検索を必須とする文を削除した最終条件になっている。
